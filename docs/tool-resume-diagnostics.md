# 工具续接超时诊断

## 用途与边界

这是临时诊断分支，不是对首次超时的修复。它基于已部署的 registry ACP
1.5.0 源码，不包含官方 CLI 1.5.9 迁移。

本次调查确认：首次工具续接约181.9秒后返回504，再次提交同一调用ID才返回400。
原失败会话已被清理，现有证据无法判断首次请求卡在哪个阶段。另一窗口的正常请求、
离线检查和fixture测试都不能替代原故障复现。

## 阶段记录如何解读

- 请求进入与解析：区分尚未完成输入处理和后续等待。
- lookup：仅表示本地是否找到仍可续接的调用。
- resume：仅表示结果通过本地校验并交给本地等待者。
- MCP reply-ready：仅表示响应准备或入队，不表示网络送达或Native消费。
- 首次ACP更新：从更新生产方观察，不根据消费者暂停推断Native无活动。
- `turn_close_started`的`cause`来自明确调用点，只表示开始关闭；`cleanup`不等于客户端取消，
  更不表示Native已经退出。它不是上游根因分类。
- SSE收尾明确区分`complete`、`tool_wait`、`error`和`client_cancel`；
  清理阶段主动abort信号不能作为客户端取消证据。

日志只记录关联ID、阶段、计数、受控原因和时间信息，不记录认证值、业务正文、
工具参数或工具结果。MCP端点的访问token不是诊断关联ID。

## 失败现场的敏感性

超时留存仅针对目标请求的Native conversation数据库及WAL，不复制凭据文件，
也不扫描模型目录探测使用的`host-acp`。库本身可能含完整业务上下文，
工具历史中也可能出现敏感值；不复制独立凭据文件不代表数据库没有敏感数据。
必须作为敏感资料保存；不要上传工单、提交Git或分享原件。

原始DB/WAL文件对不是SQLite原子备份。采集跳过、超限或源变化必须按缺口处理，
不能称为成功。等待`worker.stop()`尝试后、目录清理前取得的状态，不代表已经核验完整
Native进程树退出，也不能证明取消发生前Native是否完成。

## 留存位置与使用

位置为`<AGY_DATA_DIR>/diagnostics/timeout-scene/`：仅Native UUID命名的`.db`、
对应`-wal`和`manifest.json`。目录为0700，文件为0600。

- 仅带客户端工具的turn因请求总deadline关闭时触发；普通完成、普通取消和工具停放超时不留存。
- 单个服务实例只尝试一次（含缺源或IO失败），不轮询、不自动重试；
  最多8个数据库/WAL文件、合计64MiB。
- 目标已存在时跳过，不覆盖旧证据；重启不会自动清除已有目标。
- 发布依赖单实例、单次collector及私有目录边界，不是跨进程原子no-clobber机制。
- `stage=captured`才表示本次文件留存完成；`gap`、`skipped`及不存在的文件不能当作成功。
- 恢复时保留DB与同名WAL成对，使用识别WAL的只读SQLite连接和`backup()`产生分析副本；
  再做`quick_check`及manifest哈希核对。不要忽略WAL或直接修改原件。
- 外置`result_uri`指向的内容不在本次DB/WAL留存范围；没有取得外置内容时，不能把空inline字段
  叫作“空工具结果”。
- 记录故障时间，按`req`与`turn`串联阶段日志和manifest。仅分享受控元数据，不直接分享数据库。
- 资料无自动过期删除。由获授权的运维人员私有归档、确认已保留所需证据后处理；
  不应为重新采集而覆盖原件。

## 不改变的行为

不放宽ownership或调用ID校验，不自动重试，不把重复ID变成新调用，不延长请求或
工具等待期限。诊断失败不能覆盖原始请求错误，不能阻止Native取消。

本分支检查通过不构成部署授权，也不表示生产故障已经修复。
